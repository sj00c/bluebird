# 검색 계획: 문제 문장 → 비슷한 과거 아이디어

목적: 최근 자료(정책뉴스·법률안·법령)에서 뽑은 문제 문장으로 master의 과거 아이디어를 찾는다.
`external.doc.ideas`를 채우는 단계와 사람이 직접 찾아보는 `bluebird master search` 명령이 같은 검색을 쓴다.

## 1. 구성

| 단계 | 방식 | 값 |
|---|---|---|
| 단어 검색 | BM25. 글 = `embedding_input`, 토큰 = Kiwi 형태소 중 명사·어근·영문·숫자(`NNG NNP XR SL SN`) | k1 2.0, b 0.5 |
| 벡터 검색 | `embedding`(text-embedding-3-small) 코사인 | 각 200개 |
| 섞기 | 가중 RRF: 점수 = Σ w / (k + 순위) | k 60, BM25 0.6 · 벡터 0.4 |
| 범위(선택) | 연도·종류·분야·유형 필터. 사용자가 정할 때만 | – |
| 재정렬 | gpt-4.1-mini가 후보 중 관련 있는 것만 순서대로 최대 10개 | 후보 50개 |

GraphDB·GraphRAG는 쓰지 않는다. 한 단계 유사 검색이라 일반 RAG가 더 맞고(RAG vs GraphRAG, KDD 2026), 관계가 몇 개뿐이라 PostgreSQL로 충분하다.
한국어 전용 모델(KURE 등)은 쓰지 않는다. 지금 구성으로 충분한 성능이 나왔다.

## 2. 근거(2026-10-22 시험)

- 질문 = 2023년 이후 시민 제안의 목표 문장. A 100개(조정용), B 100개(확인용, 소스별 개수 A와 같게, seed 7)
- 찾을 대상 = 2019년 이전 사용 대상 67,788건
- 채점 = GPT-4.1이 2(같은 문제)·1(관련)·0(무관). 판정한 쌍 전체로 nDCG@10 계산

| 방식 | A nDCG@10 | B nDCG@10 | 1등이 같은 문제(A / B) |
|---|---:|---:|---:|
| 벡터만 | 0.656 | 0.685 | 55% / 50% |
| BM25 기본(명사+동사·형용사, k1 1.2, b 0.75) | 0.701 | 0.761 | 52% / 59% |
| BM25 조정(명사, k1 2.0, b 0.5) | 0.719 | 0.775 | 58% / 61% |
| 혼합 기본(k 60, 5:5) | 0.739 | 0.787 | 65% / 66% |
| **혼합 조정(k 60, BM25 0.6)** | **0.752** | **0.805** | 66% / 66% |

- 조정 값은 A에서 고르고 B에서 확인. 혼합 조정 − 기본 = A+B nDCG +0.015(부트스트랩 p 0.001)
- 조정 범위: 품사 3종 × k1 5개 × b 4개, RRF k 5개 × 가중치 5개. 상위 설정끼리 차이 ±0.005 = 잡음 수준

재정렬(혼합 조정 후보 → gpt-4.1-mini, A+B 200개):

| | 그대로 상위 10 | 후보 30 | **후보 50** | 후보 80 |
|---|---:|---:|---:|---:|
| 1등이 같은 문제 | 66% | 75.5% | **76%** | 72.5% |
| 돌려준 것 중 같은 문제 | 49.6% | 74.6% | 72.7% | 69.4% |
| 돌려준 것 중 관련 이상 | 87.7% | 97.6% | 97.2% | 96.1% |
| 질문당 같은 문제 개수 | 4.96 | 4.89 | 4.96 | 5.11 |
| 평균 개수 | 10 | 6.6 | 6.8 | 7.4 |

- 재정렬 = 관련 없는 것을 빼고 1등을 맞춤. 찾는 개수는 거의 같음 → 후보 50
- 질문 바꾸기(HyDE 등)는 넣지 않음. 문서 검색 연구에서 효과가 없거나 나빴고, 우리 질문은 이미 문제 문장

## 3. 만든 것(2026-10-23, 로컬 DB만)

1. 마이그레이션 `0019_search_tokens`: `master.search_tokens`(text, 형태소 토큰을 공백으로 이음). 사용 대상만
2. `bluebird master embed`: 벡터와 함께 `search_tokens`도 채움(글이 바뀐 행·빈 행만). `refine`이 AI 칸을 비울 때 같이 비움
3. `search.py`: 토큰화, BM25 색인(메모리), 벡터 검색(pgvector), RRF, 재정렬
4. `bluebird master search "문장"`: 결과 표 출력(읽기 전용, db_log 안 남김). 옵션 = 개수, 연도·종류·분야·유형 필터, 재정렬 끄기
5. egress: 재정렬 요청에 여러 소스 아이디어가 함께 나감 → 한 칸에 소스 여러 개를 적을 수 있게 하고, 소스마다 반출 검사
6. 문서: `docs/MASTER.md` 칸 설명·명령표

결과: 로컬 사용 대상 114,781행 토큰 채움(약 6분, 외부 호출 없음). 검색 1회 약 9초(BM25 색인 만들기 포함).
재정렬 없이 돌린 상위 10개 = 시험 결과와 같음(질문 1개 확인). 토큰이 시험과 다른 행 219개(0.3%) = Kiwi가 "로데오 거리"처럼 띄어쓰기 든 낱말을 한 토큰으로 낸 경우. 저장할 때 공백으로 나뉨(질문도 같은 방식이라 일관됨).

서버 반영 = pgvector 이미지 교체 뒤 0016~0019 한꺼번에(사용자 확인 후).

## 4. 다음

- `external.doc`에서 문제 문장 뽑기 → 이 검색으로 `ideas` 채우기
- 실제 정책뉴스·법률안 문제로 같은 시험 한 번 더(질문 형식이 다름)
- 문제가 해마다 이어진 모습(문제 지속) 보기 = 그래프 방식은 나중에 정함(2026-10-23 결정). 재료는 이미 DB에 있음: 아이디어 키(api, key)·연도·벡터·검색 토큰, 자료→아이디어 연결(`external.doc.ideas`). 그래프는 이 값들로 나중에 만들 수 있어 지금 구조를 바꾸지 않음
